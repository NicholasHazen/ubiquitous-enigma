03 · Give the wheels a vocabulary

Teach it five commands

Forward. Back. Left. Right. Stop. A small robot can get quite interesting with five words.

The wiring is ready, and the motor pack stays off while you bring up the board. Use the supplied sketch as a small firmware contract: explicit startup state, bounded commands, and a local timeout. Your programming experience carries over; the new work is checking what each software state means at the driver and the moving wheel. Keep this same firmware through the camera chapter.

On the bench · about 35 minutes

Bring: the wired Uno and shield, USB data cable, computer and this chapter. Leave the AA pack switched off.

Finish line: the Serial Monitor prints READY, accepts a command, and prints STOP timeout when you stop sending it. The wheels do not need to move yet.

03A · Get a known program onto the board

  1. Install Arduino IDE 2 from the official Arduino software page. Connect the Uno to your computer with its USB data cable.
  2. In the IDE's board selector, choose Arduino Uno and the port that appears when you plug it in. If the IDE asks to install Arduino AVR Boards, accept. Use Tools → Board → Arduino AVR Boards → Arduino Uno if you need to set it manually.
  3. Open File → Examples → 01.Basics → Blink and click Upload, the right-arrow button. The Uno's onboard L LED should blink. This checks the USB cable, selected board, port and upload tool before we involve the shield.
  4. Open Library Manager, search for Adafruit Motor Shield V2 Library, and install the library by Adafruit. Accept its dependency installation. The V2 name is correct for our #1438 v2/v3 shield. Do not install the old AFMotor library. Adafruit's library installation page shows the same package.
  5. Download the sketch below. Put rover.ino inside a folder named rover, then open it in the IDE. If the IDE offers to create that matching folder, accept. Click Verify, then Upload. The pack remains off.

The complete rover sketch · same code as the download

This is a complete Arduino sketch for the stated board and installed library. It is supplied for you to compile and test using the steps here; it has not been run on a physical rover for this edition.

// Arduino Uno R3 + Adafruit Motor Shield #1438 (v2/v3).
// Install "Adafruit Motor Shield V2 Library" with its dependencies.
// Left motor M1, right motor M2. Calibrate wire polarity on a stand.
#include <Wire.h>
#include <Adafruit_MotorShield.h>

Adafruit_MotorShield shield;
Adafruit_DCMotor *leftMotor = shield.getMotor(1);
Adafruit_DCMotor *rightMotor = shield.getMotor(2);
const int DRIVE_PWM = 90;       // Effort, not a measured wheel speed.
const int TURN_PWM = 70;
const unsigned long TIMEOUT_MS = 350;
unsigned long lastCommandMs = 0;
char requested = 'X';
char applied = '?';
bool shieldReady = false;

void setMotor(Adafruit_DCMotor *motor, int demand) {
  if (demand == 0) {
    motor->setSpeed(0);
    motor->run(RELEASE);       // Coast; this is not an active brake.
  } else {
    motor->setSpeed(abs(demand));
    motor->run(demand > 0 ? FORWARD : BACKWARD);
  }
}

void applyCommand(char command) {
  int left = 0;
  int right = 0;
  switch (command) {
    case 'F': left = DRIVE_PWM; right = DRIVE_PWM; break;
    case 'B': left = -DRIVE_PWM; right = -DRIVE_PWM; break;
    case 'L': left = -TURN_PWM; right = TURN_PWM; break;
    case 'R': left = TURN_PWM; right = -TURN_PWM; break;
    case '1': left = DRIVE_PWM; break;  // Left wheel only, forward.
    case '2': right = DRIVE_PWM; break; // Right wheel only, forward.
    default: break;                    // X means both demands stay 0.
  }
  setMotor(leftMotor, left);
  setMotor(rightMotor, right);
}

void setup() {
  Serial.begin(115200);
  shieldReady = shield.begin();
  if (!shieldReady) {
    Serial.println(F("SHIELD NOT FOUND. Power off; check headers."));
    return;
  }
  applyCommand('X');
  applied = 'X';
  Serial.println(F("READY. F B L R X; bench tests 1 and 2."));
}

void loop() {
  if (!shieldReady) return;

  // Read at most 8 bytes per visit, so timeout checking keeps running.
  for (byte count = 0; count < 8 && Serial.available(); ++count) {
    char incoming = Serial.read();
    if (incoming == '\r' || incoming == '\n' || incoming == ' ') continue;
    switch (incoming) {
      case 'F': case 'B': case 'L': case 'R': case '1': case '2':
        requested = incoming;
        lastCommandMs = millis();
        break;
      case 'X':
        requested = 'X';
        break;
      default:
        requested = 'X';       // Unknown input stops; never refreshes time.
        break;
    }
  }

  if (requested != 'X' &&
      (unsigned long)(millis() - lastCommandMs) >= TIMEOUT_MS) {
    requested = 'X';
    Serial.println(F("STOP timeout"));
  }
  if (requested != applied) {
    applyCommand(requested);
    applied = requested;
    Serial.print(F("Command: "));
    Serial.println(applied);
  }
}

03B · Talk to it while motor power is off

  1. Open Tools → Serial Monitor. Set its speed to 115200 baud and its line ending to No line ending. Press the Uno reset button once. Look for READY. F B L R X; bench tests 1 and 2.
  2. Type uppercase F and click Send. You should see Command: F, then STOP timeout and Command: X after roughly a third of a second. Nothing spins because the pack is off.
  3. Send L, then R, then B, allowing each to time out. These are requests, not measured motion.
  4. Send ?. It must not start a motion command. Send X; this explicitly requests stop. If already stopped, the sketch prints no extra line because it only reports state changes.
  5. Close the Serial Monitor, reopen it, and check that the Uno starts stopped again. Opening a serial connection commonly resets an Uno; a reset is not permission to move.
Our entire command protocol
ByteRequested wheel actionOutput setting
FBoth forward90 of 255
BBoth backward90 of 255
LLeft backward, right forward70 of 255
RLeft forward, right backward70 of 255
XRelease both motorsCoast to rest
1 / 2Left only / right only, forward90 of 255; raised-wheel checks only

Each uppercase character is a complete command. There are no numbers to append and no newline is needed. Spaces and line endings are ignored; other unknown characters stop the motors without refreshing the timer. A later camera program will send the current command every 0.1 seconds—ten times per second. After 350 milliseconds without another movement command, the Uno releases both motors.

Review three firmware contracts

Open the sketch and find DRIVE_PWM. That number sets motor effort on a scale from 0 to 255. A setting of 90 is not 90 RPM, and half the number does not promise half the ground speed. Load, friction and pack voltage all get a vote.

Review the freshness contract around lastCommandMs. A valid movement command refreshes it; elapsed time in loop() eventually changes requested to 'X'. The Uno enforces that timeout locally even when the laptop stops making progress. A successful serial write is evidence of sending a request, not evidence of motion.

Finally, find RELEASE. The driver stops driving the motor, so a moving wheel can coast. The 350 ms limit is a software deadline, not a stopping-distance guarantee. The pack switch also matters: a timeout cannot rescue a completely hung controller or a broken connection to the driver.

Verify the timeout contract on the board

With motor power off, send F once and let it expire. Repeat Bench 03B’s unknown-byte and reset checks. Compare the observed state transitions with the code before treating the board as ready for a physical test.

Expected behavior

The accepted F refreshes the command time once. Silence lets 350 ms expire, and the sketch requests X. Repeating F at ten times per second would keep it fresh. An unknown ? requests stop without refreshing the movement timer. Reset starts stopped.

Embedded timing note · loop latency and timer rollover

The input loop consumes a bounded number of bytes before returning to the timeout check. Audit any later library call or added work for how long it can postpone that check: delay(2000) would block ordinary loop checks for two seconds. Arduino's Blink Without Delay is a concise reference for the platform’s elapsed-time idiom if you need it.

The unsigned subtraction in the timeout expression handles the Uno timer wrapping around, as long as we keep checking at these short intervals. The motor library still performs hardware communication; this is a small teaching controller, not a hard real-time safety system.
