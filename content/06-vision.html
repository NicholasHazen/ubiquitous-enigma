06 · Your rover gets curious

Make it look at a blue card

A camera, a patch of blue, and a small turn. This is your first complete sense-and-act loop.

Put a blue card at the left of a camera image. The computer draws a circle on it and asks for a left turn. Move the card into the middle, and the request becomes stop. We will get that working on screen, connect it to the raised wheels, then let the rover make a few supervised turns on the floor.

The laptop handles the pictures. Your Uno keeps the motor settings and 350-millisecond command timeout from Chapter 03. Treat the boundary between them as an interface you can inspect: blue pixels become a position, the position becomes a command, and the firmware bounds the resulting drive. This hand-written perception rule gives you a baseline before introducing a learned model.

On the bench

Bring: the working rover, its laptop and USB cable, a USB webcam, a roughly 10 × 10 cm piece of bright blue card, tape or hook-and-loop straps, and a plain background. A laptop's built-in camera works for the first screen-only test; the floor experiment needs a camera mounted on the rover.

Do these sessions in order: install and see the card; check raised-wheel responses; make short floor turns. Finish one session and pack down if your attention is fading. The next numbered step will still be here.

2. Make one blue patch reliably visible

  1. Hold the card roughly half a metre from the camera, against a plain background. Adjust that distance until the card is clearly visible and fills about a tenth of the image width.
  2. Look at Blue mask. The card should be a connected white patch; most of the background should be black. A green outline and dot in the color image show the selected patch and its centre.
  3. Move the card toward the image's left edge. The overlay should say want L. Move it right: want R. Between the two yellow centre lines: want X.
  4. Remove the card completely. You should see no target and want X. Put a second blue object in view to see the limitation: the script follows the largest qualifying blue patch, not the identity of your card.

The mask is a color filter. HSV separates hue, saturation, and brightness, which makes a blue range easier to express than a mixture of red, green, and blue values. The script starts with hue 90–130 in OpenCV's 0–179 hue scale. These values are a starting point for a blue card, not a promise that every blue object works under every lamp.

If the card stays black in the mask: first move to even daylight or a bright white lamp, use a saturated blue card rather than pale blue paper, and remove blue background objects. If that still fails, quit with q, leave motor power off, and change the first two settings to LOWER_BLUE = (85, 100, 60) and UPPER_BLUE = (140, 255, 255). Save and rerun. This admits a wider range of blue-adjacent hues. Keep the wider values only if the card becomes a clear white patch while the background stays mostly black. If unrelated objects now win, restore the original values and replace the target with more saturated blue card. Do not connect the motors until the four checks above pass.

For the idea behind that change, OpenCV's inRange tutorial shows how hue, saturation, and brightness limits select pixels. It is a reference for a later closer look; you do not need to recreate its program.

Tune one control parameter against an observation

Change DEADBAND = 0.12 to 0.20 with motor power off. Predict the effect on sensitivity to small position errors, then move the card through both thresholds. The new skill is connecting a parameter to behavior you can measure.

Check your prediction

The central stop region becomes wider, so the card can sit farther from the exact image centre without asking for a turn. Return the value to 0.12 before continuing. The two yellow lines show the actual threshold.

3. Connect the letters to raised wheels

  1. Quit the script with q. Switch motor power off. Secure the USB webcam to the front of the rover, facing forward with its image level. Route and secure the camera cable away from the wheels.
  2. Set the rover on its stand so both wheels clear the surface. Connect the Uno's USB cable. Close Arduino Serial Monitor; only one program can own the serial port at a time.
  3. Run the port-list command below. Unplug and reconnect the Uno, rerunning the command each time. The port that disappears and returns is the one to use.
# Windows Command Prompt
.venv\Scripts\python.exe -m serial.tools.list_ports

# macOS / Ubuntu terminal
.venv/bin/python -m serial.tools.list_ports

The lines beginning with # above are labels; copy only your system's command. Windows might report COM4, macOS /dev/cu.usbmodem1101, and Ubuntu /dev/ttyACM0. Those are examples. Copy the device name you just identified.

  1. Run the script with that port. For Windows, an example is .venv\Scripts\python.exe camera_rover.py --port COM4. For macOS/Linux use .venv/bin/python camera_rover.py --port /dev/ttyACM0, replacing the device name. Add your tested --camera 1 if needed.
  2. Wait for LIVE | DISARMED. Turn motor power on. The wheels must stay still. Place the card in the middle of the image.
  3. Click the image window, then press Space to arm. Move the card to the image's left. You should see short left-turn wheel pulses: left wheel backward, right wheel forward. Move it right and check the opposite directions.
  4. Centre the card, hide it, and press Space to disarm, one test at a time. Each must stop driving. Press q to exit; the program attempts X before closing the serial port.

The raised-wheel test cannot centre the card by itself because the rover's body cannot turn. You move the card to test its decisions. The script sends at most ten updates per second and allows roughly 0.2 seconds of turning followed by 0.3 seconds stopped. The firmware supplies the low turn setting; the laptop does not send an unbounded speed.

Check the broken-camera case here

With wheels raised and the card off-centre, unplug the USB webcam. The camera program should stop requesting turns and disarm when no new frame arrives. If the program or laptop freezes altogether, the Uno's separate 350-millisecond timeout must release the motors. Keep your hand near the motor-pack switch; turn it off if either test behaves differently, then resolve the cause before floor trials.

The script reads continuously and keeps only its latest delivered image. Its age check measures time since the computer received that image, not the camera's actual exposure time. A driver that keeps delivering frozen or heavily delayed pictures can fool this check. A visibly lagging or frozen preview is a stop-and-fix condition.

4. Let the whole rover make a small turn

  1. Quit the script and switch motor power off. Move the rover to a clear, level floor. Keep the laptop secure nearby, with slack in both USB cables. The webcam stays fixed to the rover.
  2. Place the blue card upright just to the left of the rover's forward view. Keep its offset small: about a quarter of the image width from the middle. Restart the same script. Leave it disarmed.
  3. Turn motor power on and press Space once. The rover should nudge left, bringing the card toward the middle of its own view. Watch the cables; allow only a small turn, never a full rotation.
  4. As soon as the target is inside the yellow lines, the request should be X. Press Space to disarm. Repeat once with the card slightly right of centre.
  5. Hide the card. Confirm that motion stops. Quit with q, switch motor power off, and save a short video or a sentence describing the result.

If the target moves farther from the image centre as the rover turns, stop. Check that the camera faces forward and the manual L/R tests from Chapter 05 still match the robot's directions. The preview is not intentionally mirrored. Do not reverse a sign until you know which physical assumption failed.

If it hunts from side to side, first make the card easier to see and the camera mount firmer. Then widen DEADBAND to 0.20 and repeat a short test. If the wheels cannot start at the firmware's turn setting, return to the mechanical and battery checks in Chapter 05. Raising power without understanding a jam is a poor debugging shortcut.

The control loop you built

The blue detector uses thresholds you chose, and the controller uses a hand-written rule. Neither fits parameters from training examples. The rule measures where a colored patch appears and asks for a correction; the resulting turn changes the next image. That is feedback: the robot’s result becomes evidence for its next action. Keep this inspectable baseline when you later compare learned perception or control.

There is no forward-pursuit command in this program. A target in the middle of the picture tells us where to look, but not how far away it is or whether the route is clear. Keep that boundary as a design decision you can explain. The next robot changes the body, while preserving the habit of small commands and visible evidence.

Open the complete camera_rover.py file

Save this whole file if you are not using the download. The capture thread keeps replacing the latest frame; it never sends motor commands. The main loop makes the decision. The finally block attempts to stop on a normal exit or Python exception, and the Uno timeout remains necessary if the computer cannot run that cleanup.

"""Blue-card steering demo. Dry run unless --port is supplied; Space arms.
Requires Python 3.11+, opencv-python and pyserial. Firmware: rover.ino.
No forward motion is sent. Test raised wheels before a tethered floor trial.
"""
import argparse
import threading
import time

import cv2
import numpy as np
import serial

LOWER_BLUE = (90, 100, 60)       # OpenCV HSV: H 0..179, S/V 0..255
UPPER_BLUE = (130, 255, 255)
DEADBAND = 0.12                  # Fraction of half the image width
MAX_FRAME_AGE = 0.25             # Since capture completed, not sensor exposure
PERIOD = 0.10                    # At most 10 command updates per second


class LatestCamera:
    """Keep reading so the control loop uses the latest delivered image."""
    def __init__(self, index):
        self.cap = cv2.VideoCapture(index)
        if not self.cap.isOpened():
            self.cap.release()
            raise RuntimeError("Cannot open camera. Close other camera apps; try --camera 1.")
        self.cap.set(cv2.CAP_PROP_FRAME_WIDTH, 640)
        self.cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 480)
        self.cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)  # Best effort; backend may ignore it
        self.lock = threading.Lock()
        self.stop = threading.Event()
        self.frame = None
        self.sequence = 0
        self.stamp = 0.0
        self.failed = False
        self.thread = threading.Thread(target=self.read_loop, daemon=True)
        self.thread.start()

    def read_loop(self):
        try:
            while not self.stop.is_set():
                ok, frame = self.cap.read()
                if not ok:
                    with self.lock:
                        self.failed = True
                    break
                with self.lock:
                    self.frame = frame
                    self.sequence += 1
                    self.stamp = time.monotonic()
        except Exception:
            with self.lock:
                self.failed = True
        finally:
            self.cap.release()

    def snapshot(self):
        with self.lock:
            frame = None if self.frame is None else self.frame.copy()
            return self.sequence, self.stamp, frame, self.failed

    def close(self):
        self.stop.set()
        self.thread.join(timeout=0.5)  # A stuck camera must not delay the stop command


def locate_target(frame):
    """Return a command, normalized error, and mask; annotate frame in place."""
    hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
    mask = cv2.inRange(hsv, LOWER_BLUE, UPPER_BLUE)
    contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    height, width = frame.shape[:2]
    for x in (int(width * (1 - DEADBAND) / 2),
              int(width * (1 + DEADBAND) / 2)):
        cv2.line(frame, (x, 0), (x, height - 1), (0, 200, 255), 1)
    if not contours:
        return "X", None, mask
    target = max(contours, key=cv2.contourArea)
    area = cv2.contourArea(target) / (width * height)
    moments = cv2.moments(target)
    if not 0.003 <= area <= 0.70 or moments["m00"] == 0:
        return "X", None, mask
    cx = moments["m10"] / moments["m00"]
    cy = moments["m01"] / moments["m00"]
    error = (cx - width / 2) / (width / 2)
    cv2.drawContours(frame, [target], -1, (0, 255, 0), 2)
    cv2.circle(frame, (int(cx), int(cy)), 5, (0, 255, 0), -1)
    command = "X" if abs(error) <= DEADBAND else ("L" if error < 0 else "R")
    return command, error, mask


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--camera", type=int, default=0)
    parser.add_argument("--port", help="Arduino port, e.g. COM4 or /dev/ttyACM0")
    args = parser.parse_args()
    connection = None
    camera = None
    armed = False
    last_sequence = -1
    armed_at = 0.0
    try:
        if args.port:
            connection = serial.Serial(args.port, 115200, timeout=0.1, write_timeout=0.2)
            time.sleep(2.0)  # Uno normally resets when its serial port opens
            connection.write(b"X")
        camera = LatestCamera(args.camera)
        print("Click the image: Space = arm/disarm; q or Esc = stop and exit.")
        print("LIVE serial connected; starts disarmed." if connection else "DRY RUN: no motor commands sent.")
        while True:
            started = time.monotonic()
            sequence, stamp, frame, failed = camera.snapshot()
            fresh = (frame is not None and not failed and sequence != last_sequence
                     and started - stamp <= MAX_FRAME_AGE)
            last_sequence = sequence
            wanted, error = "X", None
            if frame is None:
                frame = np.zeros((480, 640, 3), dtype=np.uint8)
            if fresh:
                wanted, error, mask = locate_target(frame)
            else:
                mask = np.zeros(frame.shape[:2], dtype=np.uint8)
                armed = False  # Camera hiccup needs a deliberate re-arm
            # Two tenths turning, three tenths stopped: small supervised nudges.
            pulse_on = ((started - armed_at) % 0.5) < 0.2
            sent = wanted if armed and fresh and pulse_on else "X"
            mode = "LIVE" if connection else "DRY RUN"
            status = f"{mode} | {'ARMED' if armed else 'DISARMED'} | want {wanted} | send {sent}"
            if not fresh:
                status += " | waiting for fresh frame"
            elif error is None:
                status += " | no target"
            cv2.putText(frame, status, (10, 25), cv2.FONT_HERSHEY_SIMPLEX,
                        0.45, (255, 255, 255), 1, cv2.LINE_AA)
            cv2.imshow("Rover: Space arm/disarm; q stop", frame)
            cv2.imshow("Blue mask", mask)
            key = cv2.waitKey(1) & 0xFF
            if key in (ord("q"), 27):
                break
            if key == ord(" "):
                armed = not armed if fresh else False
                armed_at = time.monotonic()
                sent = "X"  # Every arm/disarm transition first requests stop
            if connection:
                connection.write(sent.encode("ascii"))
            time.sleep(max(0.0, PERIOD - (time.monotonic() - started)))
    except KeyboardInterrupt:
        pass
    finally:
        if connection:
            try:
                connection.write(b"X")
            except (serial.SerialException, OSError):
                pass  # The firmware's independent 350 ms timeout is still needed
            connection.close()
        if camera:
            camera.close()
        cv2.destroyAllWindows()


if __name__ == "__main__":
    main()

You can send manual short moves, show your five distance measurements, and make the rover turn a little to centre its blue card.
