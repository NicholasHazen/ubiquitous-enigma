Chapter 09 · The desktop workshop

Make a virtual joint move

Today's build is a robot joint you can run a thousand times without wearing out a gearbox.

If the crawler is on the bench, switch off its supply and set it aside. This software path can also run before the physical builds are complete. First you will make a virtual joint move and save its motion as a graph. Then you will ask a search program to improve the command. Treat the simulator as a small robot laboratory with explicit assumptions and repeatable inputs.

I want you to leave this chapter with two files you can point to: baseline.csv, the measurements, and baseline.svg, their picture. You do not need a graphics card, an account with a training service, or a new robot part for this exercise.

Two meanings of “model”

The MuJoCo model in this chapter specifies geometry, mass, joints, and actuator behavior; the simulator computes motion from those assumptions. A learned model instead fits adjustable parameters from examples. We will use this simulator to generate an inspectable experiment first. The first-model plan in Chapter 10 then turns that setting into a supervised-learning task. Neither result establishes that the real joint behaves the same way.

What should happen

The terminal prints final_rad: 0.400000, followed by Wrote baseline.csv and baseline.svg. Open baseline.svg in your browser. Expect the joint to wait briefly, then move toward the requested angle. Small numerical differences between systems are fine; an exception message or wildly different final angle needs a check.

3. Read the picture before changing the machine

Keep the units visible at every interface: 0.4 radians is about 23 degrees. The link begins at zero, and the request changes at 0.2 seconds. Its resulting position takes time to catch up because the model has mass and limited torque. Preserve separate fields for the target, the command actually applied, and the resulting angle; collapsing them would hide the behavior you are trying to learn.

Our link is a 100 mm capsule with a mass of 100 g. Its hinge points vertically, like a door hinge. The link sweeps horizontally, so gravity does not pull it around that axis. It has no floor contact and cannot crawl. The numbers are teaching values, not a model fitted to your SG92R servo. The XML uses meters, kilograms, seconds, and radians: 0.10 means 100 mm here.

The actuator is a simplified position controller with a limited output. The MuJoCo actuator reference describes the gain and force-limit fields. A real hobby servo also has electronics, speed limits, friction, backlash, and delays that this little model does not yet reproduce.

4. Make one deliberate change

Predict what happens if the command takes 0.30 seconds to rise to its destination. The final requested angle stays the same. Will the green curve jump faster, move more gently, or end somewhere else? Write your prediction before running the next command.

Windows:

.\.venv-sim\Scripts\python.exe joint_probe.py --ramp 0.30 --out slow

macOS or Linux:

.venv-sim/bin/python joint_probe.py --ramp 0.30 --out slow

Open slow.svg next to baseline.svg. The command now climbs gradually, and the simulated joint still arrives at about 0.4 radians. In the executed example, peak speed falls from about 3.97 to 1.53 radians per second. The movement is gentler, but it spends longer behind the desired angle. Next chapter gives a program this tradeoff to explore.

If your result differs, try these checks in order
  1. Python is not found: return to the Python setup in Chapter 06; install the specified 3.12 interpreter, then reopen the terminal before repeating step 2.
  2. It cannot find requirements.txt or joint_probe.py: the terminal is in the wrong folder. Reopen it using step 1 and confirm all three files are visible there.
  3. No module named mujoco: rerun the installation using the full environment Python path shown above. Running plain python can select a different installation.
  4. No matching distribution: first confirm you are using desktop Python 3.12 on a supported 64-bit system. Copy the entire installation error into your notes and compare its platform with the package's official installation documentation; do not install a similarly named replacement.
  5. XML parsing error: download joint.xml again and leave it unchanged for the baseline.
  6. The graph is missing: read the terminal for the first error. The files are written in the folder from which you ran the command.

"""Fieldbook joint experiment. Writes CSV and SVG; never connects to hardware."""
import argparse
import csv
import math
from pathlib import Path
import xml.etree.ElementTree as ET

import mujoco

HERE = Path(__file__).resolve().parent
TARGET = 0.4  # radians, about 23 degrees
SPEED_WEIGHT_S = 0.03  # preference, not a measured physical constant


def run_trial(ramp_s=0.0, mass_kg=0.10, target_rad=TARGET):
    if not (0 <= ramp_s <= 1 and 0.02 <= mass_kg <= 0.5 and 0 < target_rad <= 0.5):
        raise ValueError("Use ramp 0..1 s, mass 0.02..0.5 kg, and target above 0 through 0.5 rad")
    xml = ET.parse(HERE / "joint.xml")
    xml.find(".//geom[@name='link_shape']").set("mass", str(mass_kg))
    model = mujoco.MjModel.from_xml_string(ET.tostring(xml.getroot(), encoding="unicode"))
    data = mujoco.MjData(model)  # a fresh, stationary joint for every trial
    rows = []
    command = 0.0
    for step in range(1000):  # 2 simulated seconds; physics at 500 Hz
        desired = target_rad if data.time >= 0.2 - 1e-9 else 0.0
        if step % 10 == 0:  # update command at 50 Hz
            fraction = 1.0 if ramp_s == 0 else max(0.0, min(1.0, (data.time - 0.2) / ramp_s))
            command = desired * fraction
        data.ctrl[0] = command
        mujoco.mj_step(model, data)
        rows.append((float(data.time), desired, command,
                     float(data.qpos[0]), float(data.qvel[0])))
    rms_error = math.sqrt(sum((r[1] - r[3]) ** 2 for r in rows) / len(rows))
    peak_speed = max(abs(r[4]) for r in rows)
    # A teaching objective: angle error plus a preference for lower peak speed.
    cost = rms_error + SPEED_WEIGHT_S * peak_speed
    return {"cost": cost, "rms_error_rad": rms_error,
            "peak_speed_rad_s": peak_speed, "final_rad": rows[-1][3]}, rows


def save_trace(stem, rows):
    stem = Path(stem)
    with stem.with_suffix(".csv").open("w", newline="") as f:
        writer = csv.writer(f)
        writer.writerow(["time_s", "desired_rad", "command_rad", "position_rad", "speed_rad_s"])
        writer.writerows(rows)
    lines = []
    for column, color in ((1, "#a65b35"), (2, "#8b7c25"), (3, "#205e4a")):
        points = " ".join(f"{60+r[0]*310:.2f},{260-r[column]*400:.2f}" for r in rows[::5])
        lines.append(f'<polyline points="{points}" fill="none" stroke="{color}" stroke-width="2"/>')
    svg = '<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 740 320" role="img">'
    svg += '<title>Joint response: desired, commanded, and measured angle</title>'
    svg += '<rect width="740" height="320" fill="#faf7ed"/>'
    svg += '<path d="M60 40V260H680" stroke="#555" fill="none"/>'
    svg += '<g font-family="sans-serif" font-size="13" fill="#333">'
    svg += '<text x="60" y="24">Joint angle / radians</text><text x="43" y="264">0</text>'
    svg += '<text x="30" y="104">0.4</text><text x="60" y="282">0 s</text><text x="660" y="282">2 s</text>'
    svg += '<text x="75" y="307" fill="#a65b35">Desired</text><text x="170" y="307" fill="#8b7c25">Command</text>'
    svg += '<text x="280" y="307" fill="#205e4a">Measured in simulation</text></g>'
    svg += "".join(lines) + "</svg>"
    stem.with_suffix(".svg").write_text(svg, encoding="utf-8")


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--ramp", type=float, default=0.0, help="command rise time in seconds")
    parser.add_argument("--mass", type=float, default=0.10, help="simulated link mass in kg")
    parser.add_argument("--target-deg", type=float, default=math.degrees(TARGET), help="requested angle change in degrees")
    parser.add_argument("--out", default="baseline", help="output filename stem")
    args = parser.parse_args()
    metrics, rows = run_trial(args.ramp, args.mass, math.radians(args.target_deg))
    save_trace(args.out, rows)
    print(f"MuJoCo {mujoco.__version__}; ramp={args.ramp:.3f}s; mass={args.mass:.3f}kg")
    for name, value in metrics.items():
        print(f"{name}: {value:.6f}")
    print(f"Wrote {args.out}.csv and {args.out}.svg")


if __name__ == "__main__":
    main()
Under the lid: why the program has two clocks

The physics advances every 0.002 seconds: 500 steps per simulated second. The command updates every ten physics steps: 50 times per second. It stays unchanged between updates. A controller can run more slowly than its physics model; the important part is making that timing explicit. This program runs simulated time as quickly as the computer permits. Its two-second trial does not need to take two wall-clock seconds.

The CSV includes desired angle, command, resulting angle, and angular speed. Only the last two come from the simulated state. The real SG92R gives you no equivalent built-in position measurement through its three wires.

One real measurement gives the model a job

Before using a simulator to choose a physical gait, compare something you can measure. Put the Chapter 07 joint on the same vertical axis, film a small commanded movement beside a marked angle scale, and estimate its travel time. If the real joint takes longer, write that discrepancy down. Do not keep adjusting random parameters until a plot looks pleasing.

For this chapter, stop at the executable laptop result. Matching a real servo and adding a body with directional ground contact are separate builds. We will keep those jobs visible in the next chapter instead of hiding them behind an “export to robot” button.
