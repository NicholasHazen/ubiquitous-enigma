01 · Start with evidence

A room, a toy,
and twenty photographs.

Today you create the first training data and the first physical measurement. Both belong to the robot you are building.

Choose one visibly distinctive toy you can move between photographs. It could be a brightly coloured block or a particular small figure. The first model will answer a single question about a whole image: is this object visible? We will later attach that observation to where the robot was when it took the image. We are not yet locating the object within the image or deciding whether the floor is safe to cross.

Session 01A · Establish a place to return to

10 minutes · Computer, camera, tape measure · Result: one project folder and a bounded first test

  1. Create a folder called home-rover and put it under version control. Add notes/, cad/, data/, and runs/. Keep large recordings and private household images out of the code repository by default; record their local paths in your notes.
  2. Choose one room or clear section of a room with hardwood flooring. Photograph it and sketch its outline. For eventual powered tests, keep stair access physically blocked and clear the test area of pets and children. The first robot stays on this floor.
  3. Measure three accessible distances with a tape: one long span and two shorter spans in different directions. Mark exactly which surfaces define each distance. Save the sketch, measurements, and measuring method in notes/room-reference.md.
  4. Write one sentence: “The first learned observation is whether [specific object] is visible.” This stays fixed through the first training experiment.

Done: another person could identify your test area, measured endpoints, and target object from the notes.

Session 01B · Collect the first twenty examples

25 minutes · Phone or existing camera · Result: capture session A

A capture session is a related collection of images taken under one set of conditions. Neighbouring video frames often contain almost the same information. Keeping entire sessions together when we split data helps us discover whether the model works beyond the views it already saw.

  1. Create data/train/A/present/ and data/train/A/absent/. Use the camera you already have; a phone is sufficient for this experiment. Export ordinary JPEG or PNG files without location metadata if you intend to share them. Avoid including people, documents, or screens unnecessarily.
  2. Capture ten images with the chosen object visibly present and ten with it absent. Alternate between the two conditions instead of shooting all positives first. Remove the target entirely for negatives; move unrelated objects around in both conditions.
  3. Within the session, change viewpoint, distance, position in the frame, and background. Keep the target recognizable to a person. Use unique names such as A_001.jpg and put each image in its matching present or absent directory. A burst of twenty near-identical frames does not provide the intended variation.
  4. Keep the folder names as shown. Chapter 03 will generate data/manifest.csv after the full collection exists, encoding present as 1 and absent as 0. The resulting rows will look like the example below; do not create this partial CSV now.
path,session,split,label
train/A/present/A_001.jpg,A,train,1
train/A/absent/A_002.jpg,A,train,0

This two-row block illustrates the generated format. Keep all data beneath the same home-rover/data/ directory. The complete experiment will collect sessions A–H: A–D for training, E–F for validation, and G–H for the reserved final test. Every session contains both labels. Twenty images per session is an initial collection target, not a claim that 160 images will solve household recognition.

If collection feels awkward: simplify the object and use one background with several positions today. Record that limitation. The next capture session changes the setting. Do not duplicate images to fill a quota.

Done: twenty distinct files open correctly and their session and label folders are correct. The complete training program will require all three core splits; session A alone is deliberately unfinished data.

Session 01C · Measure one physical interface

15 minutes · Calipers and a screw or shaft · Result: first fit-log entry

Pick a real M3 through-bolt or smooth pin from your workshop. Measure it in more than one direction and record the reading, units, and tool. A nominal name such as “M3” tells us what family of hardware we have; it does not tell us whether a particular printed hole will let this part pass.

  1. Check that the caliper jaws are clean and read zero when closed. Measure without squeezing a compliant part.
  2. Download the fit-log template. Record the item and its measured dimensions; do not put a guessed printer tolerance in the result column.
  3. Open the mechanical workshop and identify the small coupon you will print next. Save the printer, nozzle, plate, and PLA preset you intend to use. Printing can begin in the next session.
  4. Finish notes/next-session.md with three lines: last thing that worked; evidence saved; exact next action. Today’s next action is “open Chapter 02 and print the fit coupon.”
