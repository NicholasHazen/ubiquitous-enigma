03 · A real training experiment

Teach it one visual distinction.

Your rover is still taking shape. Meanwhile, you can collect examples, fit a model, and find out what it actually learned.

Choose one distinctive toy already in your home. Our first question is deliberately concrete: “Is this particular toy visible in this image?” You will train a simple classifier, then a small neural network, and compare their mistakes. Later, the rover can attach these predictions to camera observations on its map.

This is supervised learning: you supply images and correct labels, and an algorithm adjusts model parameters to reduce prediction error. A trained classifier returns one label for the entire image. It does not yet locate the toy, identify every kind of toy, decide whether tidying is needed, or establish a clear driving route. Those are additional tasks with different evidence requirements.

Our finish line

You have a frozen dataset, a baseline, a neural-network checkpoint that reloads correctly, and an evaluation you can explain. A weak model still gives us a completed experiment when we can identify its limitations. Household recognition performance has not been established for this starter.

Download the complete model-training starter ↓

The ZIP contains learn.py, a manifest generator, pinned supporting dependencies, a dataset-schema example, a README, and executable synthetic checks. Extract those files directly into the home-rover project directory you created in Chapter 01, beside its existing data/ directory. Reuse your session A images; keep one project and dataset tree. You can begin with a phone; preserve which camera captured each session so we can later measure the change to the rover camera.

Complete this first runnable training experiment while the hardware build is still underway. An assembled rover is not a prerequisite. After the model comparison, the default route returns to the chassis layout and assembly in Chapter 02.

Session 03A · Give the experiment a fair question

45–60 minutes per visit · Continue the collection begun in Chapter 01 · Artifact: a versioned image dataset

Put the same toy on the floor, photograph it, remove it, and photograph the scene again. Repeat from different positions. If every positive picture includes your hand and every negative picture does not, the easiest useful pattern may be your hand. The computer follows the evidence we give it.

  1. Write a one-sentence label rule: 1 = the chosen toy is visibly identifiable; 0 = it is absent. Set aside ambiguous or heavily obscured cases for a later experiment. Keep the target identity fixed.
  2. Continue from the session A images captured in Chapter 01. Complete eight independently varied capture sessions, A–H, with an initial target of ten present and ten absent images in each. Change viewpoint, placement, and scene arrangement within each session; vary conditions between sessions. This gives 160 starter examples, not a claim of sufficient data.
  3. Assign A–D to training, E–F to validation, and G–H to final testing before fitting anything. A session is a real capture occasion and setup. Splitting one video into differently named clips does not make its neighboring frames independent.
  4. Use data/train/A/absent/ and data/train/A/present/, then the corresponding directories for the remaining sessions. Validation and test use their own top-level directories. Export phone images as JPEG, PNG, or WebP. Keep the original captures separately.
  5. Our model receives 64 × 64 pixels. In Session 03B, the supplied inspection command will show training images at that exact resolution. If the toy disappears at that scale, capture a closer view for this first experiment. Preserve the same resizing rule during training and inference.

The training set adjusts model parameters. Validation helps us choose an approach and checkpoint. The reserved test set estimates performance after those decisions are frozen. The reason for grouping by session is practical: two adjacent camera frames can look almost identical, so random image splitting can reward remembering a scene.

Read the grouped-data section of scikit-learn’s evaluation guide. Return when you can explain why a frame from session A should not quietly appear in both training and testing.

Done: each session contains both labels, its split is declared, and you can show varied positive and negative examples. If collection needs another visit, record the next missing session and return to your mechanical task.

Session 03B · Run the pipeline on your Windows workstation

45–60 minutes · Python 3.12 and the extracted starter · Artifact: a checked environment and manifest

Start on CPU so that your first result depends on a small software stack. The Windows 11 workstation is the default host for this lesson. Python 3.12 must already be installed; open PowerShell in home-rover, where learn.py and data/ now sit beside each other, and run:

py -3.12 -m venv .venv
$LearnerPython = ".\.venv\Scripts\python.exe"
& $LearnerPython -m pip install -r requirements.txt
& $LearnerPython -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu
& $LearnerPython smoke_test.py
& $LearnerPython make_manifest.py data
& $LearnerPython learn.py check data/manifest.csv
& $LearnerPython learn.py inspect data/manifest.csv --out reports/train-inputs.png

The explicit Python path avoids needing an activation script. Set $LearnerPython again in each new terminal. Generate data/manifest.csv once after completing the collection. It uses path,session,split,label; image paths are relative to the CSV’s directory. Inspect the generated records against your folders. The generator refuses to overwrite an existing manifest so that changing the dataset is a deliberate revision. The supplied template is a schema reference, not a second manifest to maintain.

The checker rejects missing labels, sessions crossing splits, duplicate file paths, identical file bytes, and unreadable images. Malformed records name the CSV row or image to repair. It cannot detect every near-duplicate or an incorrect human label. The synthetic smoke check creates disposable colored patterns; passing it establishes code-path behavior, not recognition of your home.

Open reports/train-inputs.png. It shows the actual 64 × 64 inputs, enlarged twofold without smoothing, with your labels. Identify the toy in several positive examples; check whether absent examples accidentally share a different background. The default preview uses training images only. Its numbered JSON sidecar preserves full paths, and --limit 24 shows more examples. This is a view of the input, not a visualization of what the network attends to.

This recipe was exercised on Linux x86-64 with Python 3.12.14 and PyTorch 2.7.1+cpu. Windows and your hardware remain execution checks for your first session. The official previous-version instructions support reproducing the chosen release. After the CPU path works, use the official installation selector for a separate CUDA environment suitable for your RTX 4090 and driver, then verify torch.cuda.is_available(). The GB10 needs its own compatible environment; an x86-64 environment is not portable to it.

If the check stops: fix the first named file or session. Preserve the declared capture groups; changing a session ID merely to silence a leakage warning damages the experiment. If installation stalls, continue photographing or printing and leave the exact error in your restart note.

Session 03C · Train the simplest useful comparison

45–60 minutes · Checked dataset · Artifact: a saved baseline and validation report

& $LearnerPython learn.py train data/manifest.csv --kind baseline --out runs/baseline

The baseline compresses each image to a 16 × 16 RGB grid, standardizes those features using training data only, and fits logistic regression. Despite its name, logistic regression is a classifier here. It learns weights that combine the pixel features into a score for “present.” This already counts as training your own model.

Open runs/baseline/validation.json. Its confusion matrix has actual labels as rows and predicted labels as columns, ordered absent then present. A false positive is an absent image predicted present; a false negative is a present image predicted absent.

Generate the per-image validation report so you can inspect which pictures produced those errors:

& $LearnerPython learn.py evaluate data/manifest.csv runs/baseline --split validation --out runs/baseline/validation-details.json
& $LearnerPython learn.py inspect data/manifest.csv --split validation --report runs/baseline/validation-details.json --out reports/baseline-validation.png

Open the PNG to see mistakes first, followed by examples near the decision threshold. Each card shows the human label, prediction, and uncalibrated score for present. Open validation-details.json for all per-image predictions and per-session results. Paths are relative to data/. Compare a failed image with a correctly classified one; a visible difference gives you a hypothesis to test, rather than proof of what the model learned.

Balanced accuracy averages the two class recalls. If a model recognizes 9 of 10 absent images and 3 of 5 present images, its balanced accuracy is (0.9 + 0.6) / 2 = 0.75. This illustrative example makes the missed toys visible even when absent images dominate. An always-absent classifier scores 0.5 on this measure when both classes occur.

The saved scaler must also process later images: fitting a new scaler during evaluation changes the representation. Read scikit-learn’s preprocessing and leakage guidance, then locate the training-only StandardScaler.fit in learn.py.

Done: you can explain one error or inspect a boundary example when this validation set has no errors, and identify which data fitted the scaler. Keep the baseline even if the neural network later wins.

Session 03D · Train filters instead of specifying them

45–60 minutes · The same frozen dataset · Artifact: a neural checkpoint and learning history

& $LearnerPython learn.py train data/manifest.csv --kind cnn --out runs/cnn-7 --seed 7 --epochs 30

A convolutional neural network learns small filters that are applied across an image. Our starter has three convolution layers with ReLU nonlinearities, spatial averaging, and two output scores. Its weights start from random initialization; no pretrained model is downloaded. Inspect make_cnn() to connect that description to the actual layers.

Training measures prediction error with cross-entropy. For one positive example, assigning the correct class probability-like score 0.8 gives a loss of approximately −ln(0.8) = 0.223; assigning 0.2 gives about 1.609. These illustrative values explain why confidently wrong predictions receive a larger penalty. The gradient describes how the loss changes with each parameter, and the optimizer uses it to adjust the weights.

Open the training loop and find zero_grad(), loss.backward(), and optimizer.step(). Follow those three operations in the PyTorch optimization lesson. The goal is to explain the update, not memorize every derivative before proceeding.

The default uses Adam at learning rate 0.001, batches of 16 images, and at most 30 epochs. One epoch visits the training set once. Validation loss selects the saved checkpoint; five epochs without improvement stop the run early. Training class counts determine the training class weights. Test results do not choose the checkpoint.

Inspect history.csv, validation.json, and run.json. The run record preserves versions, seed, preprocessing, session assignment, and hashes of the dataset and script. Saved weights are reloaded and their predictions compared before training reports success. See PyTorch’s saving and loading lesson for the distinction between architecture and fitted parameters.

Create the same detailed validation view for the neural model:

& $LearnerPython learn.py evaluate data/manifest.csv runs/cnn-7 --split validation --out runs/cnn-7/validation-details.json
& $LearnerPython learn.py inspect data/manifest.csv --split validation --report runs/cnn-7/validation-details.json --out reports/cnn-validation.png

Compare the neural model’s input cards with the baseline’s on the same validation images; the JSON indexes preserve full paths when the two sheets sort differently. Both detailed reports include per-session metrics. Preserve them beside the aggregate reports; an existing output filename is intentionally not overwritten.

If the CNN loses: inspect its errors beside the baseline’s. Check object visibility after resizing, accidental background cues, and inconsistent labels. More layers are not the first repair for missing visual evidence. If training improves while validation worsens, the saved earlier checkpoint may be the useful result.

Done: compare both validation reports and explain one training-loop update. For a later stability check, predeclare seeds 7, 19, and 43 and report all three outcomes; do not keep rerolling until one looks good.

Session 03E · Find out what survived a new capture

45–60 minutes · Frozen comparison · Artifact: an honest model report

Write down the models and preprocessing you will compare, with the supplied threshold of 0.5, before opening final test reports. Then evaluate both fixed runs:

& $LearnerPython learn.py evaluate data/manifest.csv runs/baseline --out runs/baseline/test.json
& $LearnerPython learn.py evaluate data/manifest.csv runs/cnn-7 --out runs/cnn-7/test.json

Read per-session results as well as the pooled score. Inspect the individual wrong predictions. Keep the comparison even when the simpler model wins. A score from two small test sessions is limited evidence; it does not establish performance throughout your house.

Now that the fixed test evaluation exists, you can make its error sheet:

& $LearnerPython learn.py inspect data/manifest.csv --split test --report runs/cnn-7/test.json --out reports/cnn-test.png

Test and stress previews require a matching saved evaluation report; default input previews contain training images only. Each evaluation also records the evaluator’s code and package versions and hashes of the model configuration and weights. Inspect any same_script_as_training: false result before calling it the same frozen experiment: changed inspection prose and changed preprocessing have different consequences.

Once test errors influence a redesign, those sessions have become development data. Reserve fresh captures for the next final evaluation. The code prevents report overwrites and detects a changed dataset, but good experimental boundaries still depend on your decisions.

Finally, call learn.py predict runs/cnn-7 IMAGE_PATH with an actual image path. The result contains an uncalibrated score and a label. Later, collect new rover-camera sessions as a separate stress set and use the README’s --split stress workflow. Keep those results separate from the original test. A camera or lighting change is something we measure, not something a neural network automatically handles.

Let an agent help without losing the lesson

Ask: “Trace one image from this CSV through preprocessing, training, checkpoint selection, and inference. Show which information each step may use. Then find one way this evaluation could mislead me.” You own the labels, inspect the errors, and explain the conclusion. The agent can audit code and make a contact sheet.
